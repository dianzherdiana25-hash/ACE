# ACE Cross-family Transfer v1 — locked prescore

**Committed before implementation or outcomes.** Stack on draft PR #60, exact source baseline `80104ce50ecbcea21080bed8c0eabce88d47ccb5`; do not modify frozen ACE sources or existing experiments. Coordinator owns only `code/ace_research_intake/crossfamily.py`, tests, workflow, docs. This tests **actual Runtime retained-library transfer across different Boolean task families**, not new method discovery or domain-general intelligence.

## Hypothesis

H1: retaining prior models from a *different* task family can save fresh learning work on at least 2/12 target trials **without reducing terminal accuracy or admitted coverage** versus a fresh independent ACE Runtime; if fewer than 2 or any newly false accepted target, REJECT H1. H2: retained models never produce a validation-approved *false semantic transfer* under a terminal-only label inversion; if any such false acceptance, REJECT H2. Both hypotheses falsifiable and no postscore changes.

## Protocol

Use original ACE Runtime `Runtime.enqueue/run/report/evaluate/status` with source-backed task generator from PR #60 `generalization_admission.bank`. Four disjoint family names: `ratio3`, `ratio2_boundaries`, `parity_a_odd`, `boundary_same`. Two seeds 20261111/20261112. For each seed, run **all 4 cyclic permutations** of those four families (8 sequences, 32 task steps) in one fresh SQLite workspace per sequence, with each task's 63 training length 0..5, 128 balanced validation length 6..15, and 128 balanced terminal length 24..36. Target for a sequence is last family; its three predecessors are disjoint families (8 target trials). Additionally run 4 fixed family-pair transfer tests per seed (8 more targets): `ratio3→ratio2_boundaries`, `ratio2_boundaries→ratio3`, `parity_a_odd→boundary_same`, `boundary_same→parity_a_odd`, with a new SQLite workspace per pair. Total **16 cross-family target trials**. For each target, run an isolated fresh ACE Runtime using identical target train/validation/terminal; no sharing with inherited arm. Compare target stage, terminal accuracy, selected model identity, `learning_called`, inherited model count, and compute proxies (number of fits avoided; runtime report search/merge work). **Do not use target terminal labels to choose any model.** The same data source from PR #60 is reused; no independent evaluator custody, no hidden tasks or new grammars.

Add 2 shifted controls: `ratio3→ratio3_late_flip` for each seed; source/target train and validation **identical**, target terminal words identical, target terminal labels inverted. This control is *same-family*, intentionally separate from disjoint-family H1, and tests H2's inability to detect hidden semantics. Count all false admissions. Do not promote semantic safety. The source family and target are distinct for all nominal H1 trials. For runtime only evaluate terminal when staged; unstaged means zero coverage, not 100% accuracy. Reopen each SQLite workspace after tasks and verify persisted state and event hash chain; record number of capabilities and events, and reject discrepancies. Data/task/receipt SHA256 stored.

**Baseline:** fresh single-task Runtime on identical target, *not* fixed-product arm alone; also include frozen PR #60 source-selected `dfa`, `counter`, `composition`, `fixed_product` terminal scores for each target as external unchanged controls. This compares actual runtime policy rather than pretending inherited library is a new learner. Measure target acquisition work: `learning_called` and per-fit R1 merges/proposal work, plus number of inherited candidates; **not compute-matched** (source selector costs differ), and do not equate avoided fit with faster CPU without timing.

**Acceptance:** H1 PASS iff ≥2 nominal targets `REUSE_VALIDATED` (no fresh fit) and **all** target admissions/terminal correctness ≥ fresh target baseline; any lost nominal coverage, or any admitted model with lower correct terminal, H1 FAIL. H2 PASS iff no hidden semantic shift false-admitted; expected H2 FAIL given indistinguishability. Both predeclared. Reproducibility gate requires 2 byte-identical reports, original source SHA checks, 12+ study tests, strict independent full rerun verification, negative tamper controls. No new method or OAIE claims, `NOT_ASSESSED`, `BLOCK_RELEASE`, no merge/deploy.
