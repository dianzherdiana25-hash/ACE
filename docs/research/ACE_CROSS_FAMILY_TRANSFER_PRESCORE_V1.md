## Question and falsifiable primary hypothesis

Can a representation learned from labelled binary strings improve a **graph** task, relative to fresh learning and a strong graph-specific solver, when all work, including source learning, is charged? H1 predicts that, at the primary budget, transfer will have admission-adjusted target accuracy at least as high as the best strong reference, and use at least 20% less **total CPU time** than that reference on at least four of six target task types. Source training, conversion, target fitting, validation, admission and inference are all included; no amortization in the primary result. A task counts only if its median per-seed paired cost ratio is <= 0.80 and its paired accuracy difference is nonnegative for every target size. An exact graph algorithm baseline makes this deliberately difficult: a tie in accuracy without the cost saving is not a positive result.

The mechanism may reuse or compose supplied operators; this does not claim invention of a new primitive or learning-to-learn. All hypotheses and choices here are prospective, not observed results.

## Task families and arms

- **Source family:** labelled `{a,b}` sequences. Fix six string rules before implementation: parity of `a` count; parity of length; starts with `a`; ends with `b`; contains `ab`; contains `aba`. Use only input/output labels, not rule code, to infer representations. Each source rule has a fixed 128-train/128-validation budget using length ranges 0–12 and 13–20 respectively. Deduplicate inputs within and across splits. Report source admission and cost; failed source learners stay in the report and supply no representation.
- **Target family:** simple undirected labelled graphs with a canonical upper-triangular adjacency-bit encoding (`a` = absent, `b` = present), node ordering fixed by vertex ID. Six binary targets: connectedness; bipartiteness; acyclicity; triangle existence; reachability from vertex 0 to vertex n-1; and distance from vertex 0 to n-1 at most 3. For acyclicity, disconnected forests count as true; empty graph conventions and n >= 4 are fixed in the implementation contract. Labels for target data come only from a separately implemented evaluator, not from candidate or baseline internals. Target tasks are relational graph predicates, not the source string rules. This is a cross-family stress test, not a claim that these sources encode graph invariance.
- **A transfer:** learned source representation plus a fixed, explicitly enumerated bounded target adapter. Candidate and grammar implementation must be frozen before scoring. A host LLM may propose the adapter on development examples only; its output is data, cannot alter evaluators, and must have full provenance. It cannot inspect confirmation data. Unsupported graph sizes or representation failures abstain.
- **A0 control:** same adapter and budget, but source representation trained on a fixed deterministic label permutation of each source training bank; preserves source input and label counts, breaks input/label relationships. Permutation seeds and collisions are logged. This is a causal negative control, not an assumption it will always be weaker.
- **B fresh:** the same target adapter and search budget, trained without any source representations, with fixed raw adjacency-bit features.
- **C strong fixed library:** same target adapter and budget over a human-supplied fixed library including degrees, edge count, adjacency indicators, and common-neighbor counts. Full features and costs must be specified and frozen before implementation scoring; no target labels beyond the shared train/validation data.
- **D exact graph reference:** researcher-supplied adjacency-list BFS/DFS for connectivity, bipartiteness, cycles and reachability/distance, and adjacency-bitset intersection for triangle detection. This arm has access to the known task identity and requires no target labels. It is a strong reference, not a capability discovered by ACE. Charge graph parsing, conversion and all inference work. Verify independently against brute-force truth on small graphs before any scored run.
- **E constant-negative:** always predicts false; sanity floor. All learned arms share identical labelled train/validation examples, admission policy and query limits. Exact graph D is exempt from learning and cannot be weakened to favor A.

## Units, data custody and budgets

A unit is `(task_type, graph_size, seed)`: six targets × n in {8, 12, 16} × ten seeds = 180 units. For each unit use 64 balanced train plus 64 balanced validation labels, primary budget 128 total, and 256 balanced terminal examples; abstentions count as incorrect in the primary metric. Development examples must be separate from every scored split. Input graph sets are disjoint by `(n, canonical adjacency bits)` across train, validation, probes and terminal, including across targets where the same graph is reused; graph isomorphs are grouped in the same split, not treated as independent examples. Fixed generation procedure samples each possible edge independently using densities 0.10, 0.30, 0.60 in equal requested proportions, using bounded rejection sampling for balanced labels. A stratum that cannot provide the requested count within 1,000,000 draws is `INFEASIBLE`, never silently relaxed; feasibility is checked on development seeds without terminal scoring.

The implementer freezes source, task manifests, budgets, preflight checks, and candidate-creation hash before a custodian creates a confirmation bank. Confirmation graph seeds and labels must be held by an evaluator in a separate process under a different principal or equivalent access boundary, with no candidate access to files, environment, generated labels, or score feedback until candidates and baselines are frozen. Development seeds are public and never described as sealed. If independent custody or a tested process boundary cannot be provided, **do not create or score a confirmatory bank**; a separately named public pilot may run after a new preregistration, with status `NOT_ASSESSED` and no confirmatory claim. Seeds are committed by hash before scoring and revealed with raw receipts after the bank is retired; do not repeatedly query or tune against it.

## Measurement and decision

- Primary score per unit is number correct among admitted divided by all 256 terminal samples; abstention is zero. D produces a prediction on every example. Report accuracy conditional on admission, admission rate, error counts and uncertainty by task and size. A must preserve previously admitted source-task accuracy within 0.02 absolute on a disjoint retention bank; otherwise H1 is false even if target metrics pass.
- Measure CPU time using process CPU counters on the same host and pinned interpreter, after warm-up, with one process/one core and fixed limits. Charge all candidate-creation/LLM-visible context preparation that is measurable separately, and never declare complete compute-matching if host LLM compute is unavailable. Source learning is included in each independent unit's primary cost, plus target fitting, parsing, validation, inference and containment overhead for all arms. Publish unamortized CPU and label costs, wall time, peak RSS, actual adapter operations, and host/model-call counts; secondary amortized plots must declare number of reuses. If host LLM compute cannot be measured, the total-compute superiority claim is `NOT_ASSESSED`, regardless of local CPU results.
- H1 uses per-unit paired outcomes and the task/size/seed gates above; report task-cluster bootstrap intervals with the six task types as clusters as descriptive, not a substitute for the prespecified gates. Report source-causality difference A−A0; predefined H2 passes if it is >= 0.05 absolute at every target size, with no regression to fixed library C by > 0.02. H3 drift safety reports false admissions under terminal label inversion on the same inputs, not passive detection of an unobservable change. An admission with <0.90 terminal accuracy is a false admission. Do not tune or retry on confirmation results.
- Positive evidence requires H1 and H2, source retention, baseline truth tests and all integrity/compute gates. Failure of a performance gate = `NEGATIVE`; inability to execute, unequal measured costs, inadequate labels, absent custody or unavailable host-compute accounting = `INCONCLUSIVE` / `NOT_ASSESSED`. Drift false admissions are reported separately and prevent an open-world safety claim. Even a positive result establishes only bounded evidence on these families, not OAIE or general intelligence.
