# S3 v2: intervention reversal, public development preregistration
Parent S3 v1 SHA ca080b73aa7e4ee4718800a32e15e3daabee4c50; main inspected at 5b0059b85055404a46adcdef305de81f5257486c. Prior v1 failed its improvement criterion. This is a NEW experiment, not a rerun.

Hypothesis H2: under 64 total selection labels, two environments with opposite marker-label correlations (32 chain at 0.95, 32 star at 0.05) reduce OOD false acceptance relative to a single 64-label chain environment (0.95). Evaluation is 128 branch examples at marker fidelity 0.10, from disjoint RNG seeds. Run exactly 24 paired trials, seeds 51000+11*i, i=0..23. Fixed candidate set: marker, edge-interaction parity, bit0, constant zero. The true parity label rule is NOT a candidate and is never used in selection.

Selection rule: baseline minimum total error on its 64 train labels, fixed candidate-order ties. Intervention rule: eligible if errors <= 12 on EACH 32-label source environment; choose minimum combined error, else abstain. The candidate list and threshold are fixed before results. Both receive 64 labels, score four candidates on 64 observations (256 candidate-example comparisons) per trial. Evaluation labels are never passed to selectors. Distinct topologies chain/star/branch; same underlying binary parity label, so disjoint syntax/topology but NOT disjoint semantic rule.

False acceptance: selected candidate with >32/128 test mistakes. Abstention: no selected candidate. Regret: mistakes minus hindsight best of the fixed four candidates (report only). Primary acceptance: intervention false acceptances <= baseline false acceptances - 6 of 24 AND intervention abstention <= 12 of 24; otherwise reject. No post hoc threshold tuning. Report all 24 trials, negative outcomes, CPU time, label counts, candidate comparisons, reachable OOD marker counterexamples. Adversarial controls: a no-signal source (marker fidelity 0.5), and an evaluation-label inversion sentinel proving that selectors are unchanged when only test labels change. Evaluation is PUBLIC SYNTHETIC DEVELOPMENT, not sealed confirmation. No frozen E1.4 data, paid oracle, or CI workflow.
