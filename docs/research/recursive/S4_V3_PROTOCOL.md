# S4-v3 preregistered public synthetic development protocol

Status: PRE-SCORE. This file must be committed to GitHub before running the v3 runner. S4-v1 and S4-v2 negative results remain unchanged. No claim of independent sealed evaluation.

Falsifiable hypothesis: a successor policy carrying an optimized bounded transition-change offset from previous development sequences outperforms the best equal-budget online change-point, last, flip, and fixed-arm controls by at least 5 percentage points of future cumulative reward, while losing no more than 5 percentage points to the best control on reversed adversarial transition regimes. Both gates required; otherwise REJECT. A single public synthetic split is not statistical confirmation. The successor only adjusts a policy scalar; it does NOT self-author code or architecture.

Predeclared design: 4 generations, 48 tasks per generation, 8 evaluator labels per task, 2 Bernoulli arms with P(success)=0.8 if arm matches hidden binary type and 0.2 otherwise. Hidden type transitions alternate every 12 tasks between persistence .85 and .15 on development/future; adversarial negative alternates .15 and .85. Split seeds: development 20264106+g, future 20265106+g, negative 20266106+g for g=0..3. Future/negative potential-outcome random streams disjoint from development and shared across policies (paired common random numbers). Learners never see hidden types. All policies use two forced arm pulls followed by Laplace-smoothed greedy arm choice, then infer a previous-task type from within-task rewards.

Five successor candidate offsets {-4,-2,0,2,4} are evaluated on development with exactly 8 labels/task each. Select argmax(development_success - abs(offset)), ties prefer smaller abs(offset) and smaller signed offset. Frozen selected offset is evaluated on future and negative splits. Online-change baseline uses 8-task rolling inferred-type window and switches prediction if inferred flips exceed inferred stays. Online-last always predicts the inferred last type, online-flip its complement, fixed0/fixed1 always start with the fixed arm. Successor uses the same rolling estimator with switch iff (flips - stays) > selected offset. All policies receive 8 labels per task, and each policy maintains its own inferred history. No future evaluation rewards influence selected offset.
