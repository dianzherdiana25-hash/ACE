# S4-v4 PRE-SCORE protocol — inherited transition priors (PUBLIC SYNTHETIC)

Scientific status: exploratory development, NOT sealed confirmatory evidence. This protocol must be committed BEFORE executing the runner. Earlier S4-v1/v2/v3 REJECT remain immutable. Unlike v3, the successor must carry a numerical prior across generations. It is still policy optimization, not self-authored code or architecture.

Hypothesis: a bounded inherited transition prior (Beta counts) learned from previous generation development sequences increases FUTURE total Bernoulli reward by >=5 percentage points over the strongest matched-budget non-inherited adaptive baseline, while losing <=5pp to the best control on reversed-transition adversarial sequences. Both gates required; else REJECT. No retuning after score.

Design: 4 generations, 48 tasks/generation, 8 pulls/task, two arms; P(reward|matching latent)=0.8, otherwise 0.2. Latent transition persistence for FUTURE/development is 0.85 on odd 12-task blocks and 0.15 on even blocks, reversed for NEGATIVE. Each generation uses separate development seed 20267106+g, future 20268106+g, negative 20269106+g. Independent streams, common random numbers across policies; type never directly visible to learner. Within each task first two pulls force both arms, remaining six choose smoothed greedy; infer latent type from reward rates (no oracle). Each policy has its own inferred-type history. Posterior updated ONLY from development inferred transitions, never future/negative.

Policies: successor inherited Beta(a,b) initialized (1,1) and updated with development inferred same/flip counts across generations; baseline reset Beta(1,1) each generation using only current development; baseline online-last; baseline online-flip; fixed0; fixed1. Both successor and reset get identical per-generation development labels and use posterior mean >.5 to predict same versus flip, never accessing future evaluation. All controls receive equal future/negative label budget; baseline reset also receives same development labels, while simpler controls are granted but discard these labels. Report inherited prior before and after each generation. No policy updates from evaluation rewards across tasks beyond within-task inferred history, except online-last/flip which use their previous inferred type.

Predeclared counts: 4*48*8*6=9,216 development labels; 9,216 future labels; 9,216 negative labels; total 27,648 simulated label presentations. Six policies; 1,536 evaluation labels per policy per split. Acceptance future >=77 more successes than strongest control and negative gap >= -76 successes (integer gate). CPU process_time, deterministic seeds, and all generation-level results reported. Stop after four generations even on failure; no paid oracles, external actions, hidden holdout or automatic scientific promotion.
